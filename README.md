# 稀疏体数据的游程连通组件（RLE Connected Components）

离线、纯标准库的可复用 Python 库：对**三维体按行压缩的半开 x 游程**做
连通组件标记（connected-component labeling），不展开整个体素，任何时刻只保留
当前切片与前一切片的游程。提供两个入口：

* **二值入口 `label`**：输入 `(start, end)` 游程，输出每组件体素数、
  包围盒、暴露面面积；
* **多材料入口 `label_materials`**：输入 `(start, end, material)` 游程，
  只有同种材料才合并，额外输出每组件材料号、**对空白**暴露面积，以及
  组件对之间的**接触面积**（仅共享方形面）。

## 运行环境

* Python **3.14.7**（仅使用 3.14 标准库；不依赖任何第三方包，无需网络）。
* Linux 原生运行；装好 Python 后无需 `pip install` 任何东西。
  仓库里的 `requirements.txt` 无实际依赖内容。

## 准确命令

在仓库根目录执行：

```bash
# 必要测试（独立 BFS 参考 + 手算小例 + 错误语义，含多材料）
python -m unittest discover -s tests -v

# 固定输入演示：二值三种邻接 + 多材料小体 + 两个被实际触发的非法输入拒绝
python demo.py
```

demo 只做真实小规模计算，实测约 0.05 秒（远小于 90 秒），不 sleep、
不读外部数据、不打印预录结果。

## 公开接口

### 二值入口

```python
from rle_components import label, Run, BoundingBox, Component, LabelResult

result = label(runs, depth, height, width, connectivity=6)
```

* `runs`：`[z][y] -> [(start, end), ...]`。固定 (z, y) 的一行内，游程为
  沿 x 轴的**半开区间 `[start, end)`**；每行游程必须按 `start` 升序、
  互不重叠（端点恰好相接合法，重叠非法）。游程元素可为
  `(start, end)` 元组/列表、`Run(start, end)` 或
  `{"start": int, "end": int}` 字典。空行用 `[]` 表示。
* `depth / height / width`：z / y / x 方向尺寸，整数，均在 `[1, 512]`。
* `connectivity`：
  * `6`：仅面接触（坐标差 L1 = 1）；
  * `18`：面 + 边（恰两个坐标差为 1），**不含角**；
  * `26`：面 + 边 + 角（三个坐标差均为 1）。

返回 `LabelResult`（frozen dataclass）：

| 字段 | 含义 |
| --- | --- |
| `run_labels` | 与输入同形 `[z][y] -> [component_id, ...]`，顺序对应该行游程 |
| `components` | `Component` 列表，ID 为 1 起始的连续整数 |
| `connectivity` / `num_runs` | 实际连通性 / 输入游程总数 |

`Component` 字段：`id`、`voxel_count`（体素数）、`bbox`（半开
`BoundingBox(min_z,min_y,min_x,max_z,max_y,max_x)`，各区间 `[min,max)`）、
`exposed_area`（暴露面面积，单位为体素面）、`min_z/min_y/min_x`（组件按
字典序最小的体素坐标，即 ID 排序键）。

### 多材料入口

```python
from rle_components import (
    label_materials, MaterialRun, MaterialComponent, Contact, MaterialLabelResult,
)

result = label_materials(runs, depth, height, width, connectivity=6)
```

* `runs`：`[z][y] -> [(start, end, material), ...]`，几何规则与二值入口
  相同（半开、有序、互不重叠、端点相接合法）；`material` 为**非负整数**，
  空白区域仍由没有游程表示。游程元素可为三元组/列表、
  `MaterialRun(start, end, material)` 或
  `{"start": int, "end": int, "material": int}` 字典。
* 尺寸、游程数上限与 `connectivity` 含义同二值入口；**只有材料相同的
  游程才按连通性合并**，不同材料即使面贴面也分属不同组件。

返回 `MaterialLabelResult`（frozen dataclass）：

| 字段 | 含义 |
| --- | --- |
| `run_labels` | 与输入同形的每游程组件 ID |
| `components` | `MaterialComponent` 列表，ID 1 起始，按最小 (z,y,x) 升序 |
| `contacts` | `Contact(component_a, component_b, area)` 列表，按 (a, b) 升序 |
| `connectivity` / `num_runs` | 实际连通性 / 输入游程总数 |

`MaterialComponent` 在二值 `Component` 基础上多一个 `material` 字段，且
`exposed_area` 只对**空白**（无游程区域，含体积外侧）计数：
`exposed = 6*体素数 - 2*内部面数 - 与其他组件的接触面总数`。

接触面积只统计两组件**共享的方形体素面**（面相邻的体素对数）；边、角
接触面积为 0，选择 26 邻接不会多算面积。每对组件按较小 ID 在前只输出
一次。同材料但不连通的组件分别统计；换连通模式使组件合并时，接触表与
编号同步重算。同材料相邻游程无论输入是否分段（一条长游程切成几段），
最终结果完全一致。另提供 `component_at(z, y, run_index)` 与
`contact_between(cid_a, cid_b)` 两个查询辅助。

组件 ID 按组件最小体素坐标 **(z, y, x) 字典序**升序分配。注意该排序键不
必然等于几何包围盒的 `(min_z,min_y,min_x)`：在 18/26 邻接下，几何上
`y`/`x` 更小的体素可能只出现在更大的 `z` 切片（测试中明确覆盖此区别）。

## 输入上限（接口边界）

* `depth`、`height`、`width` 各 `<= 512`；
* 游程总数 `<= 20000`（两个入口相同）；
* 坐标必须为整数，`0 <= start < end <= width`；
* 多材料入口的 `material` 必须为 `>= 0` 的整数。

这些是硬接口边界，超限一律拒绝；演示与测试不穷举上限规模，但包含
恰为 20000（接受）与 20001（拒绝）的边界测试。

## 错误语义

所有契约违背抛 `rle_components.InvalidVolumeError`（`ValueError` 子类），
消息带可定位前缀（如 `z=0 y=1 run=2.start`），**不静默纠正、不截断**：

* 数值坐标拒绝 `NaN` / `+Infinity` / `-Infinity`；
* 整数参数（尺寸、坐标、connectivity、material）拒绝 `bool`
  （`True/False` 不充当 1/0），也拒绝 `6.0` 这样的 float——必须是真正的
  `int`；`material` 另外还必须非负；
* 尺寸越界、connectivity 不是 6/18/26、空游程、坐标越界、行内游程重叠或
  乱序、嵌套结构尺寸与 depth/height 不符、游程数超 20000、多材料游程
  缺 `material` 字段等均拒绝。

两个入口都是无状态纯函数：输入要么完整通过校验后一次性产出结果，要么
抛异常，不存在部分结果或部分变更。

## 算法与设计取舍

1. **扫描 + 并查集**。按 z 递增扫描；每条游程在 DSU 中建一个节点，与
   * 同行前一条游程（仅端点相接时，x 方向面接触）、
   * 同切片 `y-1` 行（面/边）、
   * **前一切片的 `y-1`、`y`、`y+1` 三行**（面/边/角）
   做半开区间触达判定。二值入口直接合并；多材料入口只在材料相同且满足
   连通性时合并。跨切片必须扫三行：(当前 y, 前片 y+1) 这类游程对无法靠
   处理其他行覆盖；同切片 y 方向只需扫 y-1，行对 `(y-1,y)` 在处理 y 时
   恰好计一次。
2. **区间扫描线性化**。行内游程有序，配对时用单调游标跳过不可能触达的
   游程，单行配对为 `O(len(a)+len(b)+触达对数)`，整体近似
   `O(R + 触达游程对)`，`R` 为游程数；区间重叠长度直接给出共享面的
   体素列数。
3. **不展开体素**。内存只与游程数和两个切片相关（DSU 每节点常数个数组：
   父指针、体素数、z/y/x0/x1，多材料再加一个材料号）。20000 游程量级下
   实测 26 邻接全稀疏体约 0.14 秒；多材料 20000 条 512 长游程（千万级
   体素）实测约 0.17 秒，不会退化为逐体素工作。
4. **面积精确计数**。扫描时在 x/y/z 三个面方向各把每个面邻居计一次
   （同游程内部 `length-1` 个面、行内相邻、行间/切片间重叠列）。
   二值：`exposed_area = 6*voxel_count - 2*internal_face_count`。
   多材料：并查集完成后把面邻居对按根分类——同根为内部面，异根（必为
   异材料）累进该组件对的接触面积；
   `exposed = 6*体素数 - 2*内部面数 - 接触面总数`。
   边/角接触不共享体素面，故不影响任何面积（三种连通性下面积定义一致）。
5. **排序键与包围盒分离聚合**。节点按 (z,y,行内序) 创建，DSU 根第一次
   被遇到的位置即组件字典序最小体素；几何包围盒独立取各轴 min/max。

## 数值口径 / 误差

模块的全部输出（体素数、包围盒、面积、接触面积、ID）都是**精确整数运算，
不产生任何浮点结果**，因此不存在浮点误差或容差问题。唯一接触浮点的地方
是输入校验：显式拒绝 NaN/Infinity，且 float 坐标/材料号（即使是 `6.0`
这种整数值 float）不被当作合法整数。

## 测试策略与独立性

`tests/reference.py` 是**完全独立**的参考实现：把游程展开成体素集合后用
BFS 求组件（多材料版只在材料相同时扩展前沿）、逐体素逐方向数暴露面与
组件间接触面；它不导入、不调用 `rle_components` 的任何代码。
`tests/test_core.py`（二值）与 `tests/test_materials.py`（多材料）的随机
对照用例以参考实现的输出为期望值（组件标签、体素数、包围盒、面积、材料、
接触表逐字段比对），另含手算小例和题面点名场景：

* **仅角接触**：对角链在 6/18 下分开、26 下合并；异材料角接触任何
  连通性下都不合并、接触表为空；
* **不同材料交错**：同行 1-2-1 交错，接触面积与对空白暴露面积手算对照；
* **跨切片相贴**：相邻 z 切片异材料，接触面积 = x 重叠列数；
* **接触面积与连通性无关**：2x2 板相贴在 6/18/26 下接触面积恒为 4；
* **分段等价**：同材料长游程切成 1/2/3 段，组件与接触表完全一致；
* **空行/空切片/空体**；
* **编号随连通性变化**：18/26 合并组件后 ID 与接触表同步更新；
* **跨 slice 桥接**（二值）：经边接触在 18/26 下连通、6 下断开；
* **单个长游程 / 20000 条长游程**：验证核心按游程工作，不退化为逐体素。

“核心结果自身往返一致”不作为正确性依据，只做补充断言（体素守恒、ID 连续
有序、面积非负等）。

## 已知限制（按本题契约的有限子集）

* 只实现本题规定的 6/18/26 三维栅格连通性与按行 x 游程输入，不宣称兼容
  ITK/VTK/`ndimage` 等行业库的全部标签选项、像素类型或流式协议。
* 不做体素展开后的形态学操作、不输出体素级标签体（设计上避免展开）。
* 输入须一次性给出全部切片；不支持增量追加切片的有状态 API。
* 尺寸与游程数上限为题面给定的 512 / 20000；超过即拒绝而非自动外存化。
* 材料号只要求是非负整数，不维护材料名称/调色板等元数据。
