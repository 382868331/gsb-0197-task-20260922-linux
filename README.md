# runcc — 稀疏体数据的游程连通组件

对三维二值体做连通组件标记（connected-component labeling）。输入是**每行有序、
不重叠的半开 x 游程**，算法不展开整个体，逐切片扫描并用并查集合并，输出每个
游程的组件 ID、每组件的体素数、半开包围盒与面暴露面积。面向离线医学图像内核
工程，纯 Python 标准库实现，核心算法未使用任何第三方同类实现。

## 运行环境

- Python **3.14.7**（仅使用标准库：`dataclasses`、`bisect`、`math`、`unittest` 等）
- Linux 原生运行；安装 Python 后**无需安装任何其他依赖**
- 完全离线：不需要网络、账号、密钥、数据库、中间件、云 API 或 Docker

## 快速命令

```bash
python -m unittest discover -s tests -v   # 必要测试（独立 BFS 参考 + 随机全量比对）
python demo.py                            # 固定输入演示（实测约 0.03 秒）
```

## 公开接口

```python
from runcc import Run, label_volume

result = label_volume(dims, runs, connectivity=6)
```

- `dims`: `(nx, ny, nz)`，每维整数且 `1 <= 值 <= 512`。
- `runs`: `Run(z, y, x0, x1)` 或普通 4 元组的有限序列，表示体素行 `(z, y)`
  上的半开 x 区间 `[x0, x1)`（即包含 x0，不包含 x1）。
  - 坐标范围：`0 <= z < nz`、`0 <= y < ny`、`0 <= x0 <= x1 <= nx`；
  - 同一 `(z, y)` 行内游程必须**不重叠**（允许端点相接，如 `[0,3)`+`[3,5)`，
    相接处算面邻接）；行内无需预先排序；不同行/不同切片的顺序任意；
  - 允许空游程 `x0 == x1`：不参与标记，其标签为 `None`；
  - 游程总数（含空游程）**<= 20000**，正长度游程同样受此上限约束。
- `connectivity`: `6`（仅面接触）、`18`（面 + 12 条边接触，不含角）、
  `26`（面 + 边 + 8 个角，全邻接）。

返回不可动 `LabelingResult`：

| 字段 | 含义 |
| --- | --- |
| `dims` / `connectivity` | 回显的实际参数 |
| `labels` | 与输入 `runs` 等长、按下标对齐的组件 id 元组；空游程为 `None` |
| `components` | 按 id 升序的 `Component` 元组 |
| `num_components` | 组件数（含空体为 0） |

`Component` 字段：

- `id`：从 1 开始的连续整数，**按组件最小体素 `(z, y, x)` 升序**编号；
- `origin`：该最小体素 `(z, y, x)`；
- `voxel_count`：体素总数；
- `bbox`：`BoundingBox(x0, y0, z0, x1, y1, z1)`，**半开**区间，
  即 `x∈[x0,x1)`、`y∈[y0,y1)`、`z∈[z0,z1)`；
- `exposed_area`：暴露的单位体素**面**数（整数，见下）。

## 邻接定义

两游程连通当且仅当存在体素对满足下表（`dx,dy,dz` 为坐标差绝对值）：

| 邻接 | 面 `(|·|₁=1)` | 边（恰两个坐标差为 1） | 角（三个坐标差均为 1） |
| --- | --- | --- | --- |
| 6 | ✓ | – | – |
| 18 | ✓ | ✓ | – |
| 26 | ✓ | ✓ | ✓ |

游程间的 x 向求交规则：

- **面共享**：x 区间开相交（长度 `min(x1)-max(x0) > 0`），且方向允许
  （同切片 `|dy|=1,dz=0`，或跨切片 `|dz|=1,dy=0`）；
- **边接触**：区间在端点相接（相交长度恰 0 且端点相等），对应 `|dx|=1`；
  同切片 `|dy|=1` 与跨切片 `dy=0` 的方向在 18/26 下连通；跨切片
  `|dy|=1` 且 x 开相交也是边接触；
- **角接触**：跨切片 `|dz|=1`、`|dy|=1`、`|dx|=1`，仅 26 连通。

## 暴露面积口径

`exposed_area` 是组件表面的单位体素面数量，按 **6 邻接（面）**定义，与
`connectivity` 选择无关：边接触与角接触**不**减少面积。精确整数恒等式：

```
exposed_area = 6 * voxel_count - 2 * (组件内 6 邻接体素面对数)
```

实现上以游程为单位初始记账 `4L+2`（L 为游程长度），再对每处跨游程面共享
逐面从两侧各扣 1，全程整数运算，**没有浮点、没有容差**，因此不存在用宽容差
掩盖边界错误的问题。体积边界（体表面）自然计入暴露面。

## 错误语义

非法输入抛出可定位错误（消息带参数路径，如 `runs[3].y 超出 [0, 9]`），
不静默纠正、不做猜测式修补：

- `TypeError`：整数参数收到 `bool`（明确拒绝，Python 中 `bool` 虽是 `int`
  子类也不接受）、收到 `float` 或其他非整数类型；`dims`/`runs` 结构类型错误。
- `ValueError`：坐标或维度越界、`x0 > x1`、NaN/Infinity（`float('nan')`、
  `float('inf')` 出现在数值字段时）、同行游程重叠、游程长度字段数不对、
  `connectivity` 不在 `{6,18,26}`、维度或游程数超上限。

所有校验在任何标记计算之前完成；函数无对外可观察的状态，一次失败不会给后续
调用留下部分变更。本问题不存在搜索过程，故无“预算耗尽”这一结果类别。

## 设计取舍

- **不展开体**：仅持有当前切片 `z` 与前一切片 `z-1` 的游程行结构（更早切片
  及时丢弃），空间随游程数而非 `nx*ny*nz` 增长；512³ 的空体也只付常数成本。
- **单遍扫描 + 并查集**：游程按 `(z,y,x)` 扫描序编号，每个新游程只检查
  同前行、本切片上下行、前一切片 `dy∈{-1,0,+1}` 至多 6 条相关行；相关行内
  用 `bisect` 定位 x 候选窗口，仅与真正可能邻接的游程求交。
- **统计随合并精确维护**：体素数按游程长度求和，包围盒、最小体素按根聚合，
  面积按上述记账法，最后统一 `find` 压缩并重排 id。
- 确定性：相同输入输出完全一致，id 仅由组件最小 `(z,y,x)` 决定，与输入
  游程顺序无关。

近上限实测（开发机，仅供参考，非交付测试）：20000 游程稠密体约 85–160 ms，
稀疏散布约 120 ms。

## 测试与独立参考

- `tests/reference.py`：**独立**参考实现，自行把游程展开成体素集合，做
  BFS 组件标记，逐体素逐面统计面积；它不导入、不调用被测核心。
- `tests/test_runcc.py`：
  - 角接触（6/18 分离、26 合并）、边接触（同切片与跨切片）、空行/空游程、
    跨 slice 桥接、面积精确值（单体素 6、双体素 10、2³ 立方体 24 等）；
  - 80 个随机小体素（密度、尺寸随机，部分乱序输入）在三种邻接下与 BFS
    参考全量比对（id、origin、体素数、包围盒、面积、逐游程标签）；
  - id 排序、标签与输入下标对齐；
  - 全部错误语义（NaN/Infinity、bool、float、越界、重叠、上限、畸形结构）；
  - `demo.py` 子进程冒烟（退出码 0 且确实打印了拒绝边界）。
- 往返一致（labels ↔ components 互相对应）仅作为补充断言。

## demo.py

固定确定性输入：一个 5 体素核心游程 + 一个仅边接触体素 + 一个仅角接触体素
+ 一个孤立体素。三种邻接下组件数分别为 **4 / 3 / 2**，并真实调用一次含 NaN
坐标的输入，实际捕获并打印 `ValueError`（不是预录文本；不使用 sleep）。

## 已知限制 / 范围声明

- 仅实现本题契约：直角网格、二值体、6/18/26 三种邻接、半开行游程输入；
  不宣称兼容 ITK/VTK/cc3d 等行业库的完整接口与惯例（如标签类型、周期边界、
  多通道等均不支持）。
- 输入上限即题面接口边界（维度 <= 512、游程 <= 20000）；超限直接拒绝，
  不分块外溢处理。
- 面积只定义单位体素面计数；不做平滑表面（marching cubes）、不输出网格。
- 纯 Python 单线程；目标规模下延迟为亚秒级，非吞吐向 SIMD/GPU 内核。
